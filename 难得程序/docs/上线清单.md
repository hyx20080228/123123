# 上线清单（从代码到客人能扫到）

> 资质政策微信会调整，下面的数字和材料名以**微信公众平台后台当时显示的为准**，这里只是先让你心里有数。

## 一、账号这一步

小程序的一般顺序是：**注册 → 认证 → 备案 → 提交审核 → 发布**。[参考](https://blog.pospal.cn/kb/21699)

| 事项 | 说明 |
|---|---|
| 注册主体 | 用**酒馆的营业执照**注册（个体工商户或企业都行）。个人主体注册不了微信支付，二期点单会卡死，所以一开始就用执照注册 ([来源](https://www.xinlingshou.com/contents/articles/45458.html)) |
| 认证费 | 个体工商户 30 元 / 企业 300 元，每年一次 ([来源](https://blog.pospal.cn/kb/21699)) |
| 小程序名字 | 建议和执照名有关联，比如「难得民谣」。**没有食品经营许可证时，名字里尽量别出现「餐饮」「外卖」「点餐」这类词**，否则后面补类目和备案会被卡 ([来源](https://blog.pospal.cn/kb/21699)) |
| 备案 | 2023 年起小程序也要做 ICP 备案，走微信后台提交，通常几个工作日到两周，**备案没过不能发布**，要留出时间 |

## 二、服务类目

一期只做订座、不卖东西、不收钱，类目可以选得很轻；二期点单收钱就必须补餐饮类目。

| 阶段 | 类目 | 需要的资质 |
|---|---|---|
| 一期（订座、展示演出） | 通用类目，例如「生活服务 - 百货超市」这类不需要额外资质的；外加休闲娱乐/酒吧相关类目 | 营业执照即可 ([来源](https://blog.pospal.cn/kb/21699)) |
| 二期（扫码点单、线上收款） | 餐饮相关类目 | **《食品经营许可证》**（或《卫生许可证》《小餐饮登记》等同等效力证件）([来源1](https://developers.weixin.qq.com/minigame/product/mini-store/leimuzizhi/qiyeleimu.html) · [来源2](https://www.finclip.com/news/f/68568.html)) |
| 如果卖瓶装酒/预包装食品 | 商家自营 - 食品饮料 / 酒类 | 《食品经营许可证》或《预包装食品销售备案凭证》等 ([来源](https://developers.weixin.qq.com/minigame/product/mini-store/leimuzizhi/qiyeleimu.html)) |

> 注意：「点餐平台」「外卖平台」这种类目要求《增值电信业务经营许可证》，那是给**平台方**（美团那种）用的。
> 自己一家店给自己店点单，走的是餐饮服务场所那条线，不需要 ([来源](https://www.finclip.com/news/f/68568.html))。
> 真要提交前，在后台类目列表里按实际名称核对一遍。

## 三、代码里必须替换的东西

| 位置 | 现在是 | 要换成 |

| `project.config.json` → `appid` | `touristappid` | 你注册下来的真实 AppID |
| `utils/data.js` → `shop.address / tel / latitude / longitude` | 占位 XX 路 123 号 | 真实地址和经纬度（导航要用） |
| `utils/data.js` → `zones` | 示例 17 张桌 | 店里真实桌号、人数、低消 |

## 四、上云（强烈建议在店里试点前做完）

现在所有数据存在客人自己手机里，**换台手机就看不到，店员也看不到客人的单**——
所以一期试点前至少要把数据搬到云端。最省事的是微信云开发：

1. 开发者工具 → 云开发 → 开通环境（基础用量免费够一家店用很久）
2. `app.js` 里打开 `wx.cloud.init({ env: '你的环境ID' })`（代码里已经留好注释位置）
3. 建两个集合：`orders`（预约单）、`config`（店铺/桌位/节目单，方便以后做后台改）
4. 写三个云函数，把 `utils/api.js` 对应方法换掉：
   - `createOrder`：**事务**判断这张桌这个时段有没有被占，没占才写入（防两人抢同一张桌）
   - `listMyOrders` / `cancelOrder`：按调用者 openid 过滤
   - `staffOps`：店员操作，校验 openid 是否在白名单里
5. 数据库权限设成「仅创建者可读写」，店员操作一律走云函数

## 五、体验上还值得补的

| 功能 | 为什么 | 大概工作量 |
|---|---|---|
| 微信一键获取手机号 | 客人少打 11 位数，转化会明显变好（需要认证后的主体） | 半天 |
| 订阅消息 | 「您的座位已确认」「今晚 20:30，位置给您留着」—— 到店率会提升 | 一天 |
| 店员端换成独立小程序/后台 | 现在的口令页够试点，长期要独立权限 | 二期一起做 |
| 客人画像 | 来过几次、喜欢坐哪、上次点了什么——这是替换美团后最值钱的东西 | 二期 |

## 六、发布流程备忘

```
开发者工具「上传」 → 微信后台「版本管理」
   → 先发「体验版」，给自己和服务员扫码用一周
   → 没问题再「提交审核」（填好类目、测试账号、功能说明）
   → 审核一般 1~3 个工作日，过了点「发布」
   → 后台生成小程序码，打印出来贴在每张桌子和门口
```

审核时常见被拒原因，提前避开：

- 类目和实际功能不符（做了点单却没补餐饮类目）
- 页面有「敬请期待」的空功能入口 → 我的页里「线上点歌」「扫码点单」两项在提审前**先隐藏掉**（`pages/mine/mine.wxml` 里删掉那两个 `mcell` 即可）
- 收集手机号没有隐私协议 → 补一个简单的《隐私保护指引》，后台有模板
- 涉及酒水展示要注意未成年人相关提示，一期只订座不展示酒单，风险低
