# 难得民谣 · 订座小程序 产品说明（一期）

## 1. 为什么先做订座

点单是最后要啃的骨头（涉及支付、出品、对账、员工习惯），一上来就换美团风险太大。
订座是**最小又最像样**的切口：

- 不碰钱，不碰出品流程，出错也不会影响当晚营业
- 客人用一次就记住了「这家店有自己的小程序」，为二期点单攒了入口和用户
- 店里能开始攒**自己的客人数据**（谁来过、什么时候来、几个人、喜欢坐哪），这是美团不会给你的
- 服务员只要学一件事：看吧台那一页，确认 / 到店

## 2. 一期范围

**客人侧**

| 页面 | 干什么 |
|---|---|
| 首页 | 招牌、今晚唱什么、今晚还剩几桌、一个大按钮「订一张桌子」、地址电话、到店须知 |
| 订桌 | 四步在一页里：挑日子 → 几点到 → 几位朋友 → 桌位图点桌 |
| 确认 | 票根式摘要 + 称呼 / 手机号 / 留言（可点标签：过生日、想点歌、要安静角落…） |
| 订座凭条 | 取号、桌位、低消、条码、到店三步；可取消、换时间、打电话、导航 |
| 我的预约 | 还没去 / 去过的两栏 |
| 演出 | 两周歌单，今晚高亮，点一天直接订那天 |
| 我的 | 名片（称呼 + 订过几次）、菜单、小程序三期路线图 |

**店里侧**

| 页面 | 干什么 |
|---|---|
| 店员模式 | 口令进入 → 今天几桌几人几个待确认 → 每条可「确认留座 / 已到店 / 结账完成 / 取消」，可一键打客人电话 |

## 3. 订座的状态流转

```
客人提交
   ↓
 pending  待确认 ──(吧台确认)──→ confirmed 已确认 ──(到店)──→ seated 已到店 ──(结账)──→ done 已完成
   │                                 │
   └────────(任意一方取消)────────────┴──→ cancelled 已取消
```

- 桌位保留 15 分钟，过点不来吧台可以直接取消，桌子放回去
- 「已订出」的桌子在别的客人的桌位图里会显示成斜纹、点不动

## 4. 桌位怎么分（可改）

| 区 | 名字 | 桌数 | 平日低消 | 周五周六 | 特点 |
|---|---|---|---|---|---|
| A | 临窗卡座 | 4 | ¥288 | ¥388 | 靠窗软沙发 |
| B | 中庭散台 | 6 | ¥188 | ¥248 | 正对舞台 |
| C | 吧台高位 | 5 | ¥88 | ¥128 | 一个人来也行 |
| D | 里间小厢房 | 2 | ¥688 | ¥888 | 可关门，聚会生日 |

桌位图把**舞台画在最上面**，往下依次是 A / B / C / D，最底下写「门口」——
客人一眼能看懂「我坐的地方离台子有多远」，这比美团那种纯文字选桌直观得多。

## 5. 民谣风格是怎么做出来的

不是贴几个吉他图片，是整套视觉规则（都在 `app.wxss` 顶部，可改）：

| 元素 | 做法 |
|---|---|
| 底色 | 牛皮纸 `#F6EFE3` + 两层很淡的圆点做纸张颗粒 |
| 卡片 | 米白 `#FDF9F0` + 1px 浅棕描边 + 向下 3px 的硬阴影（像纸叠在纸上，不用模糊投影） |
| 主色 | 威士忌琥珀 `#C2743A`，按钮带 3px 实心下沿，按下去会「踩下去」 |
| 辅色 | 苔绿 `#5F6B51`（已确认）、酒红 `#8C3B2E`（紧张/取消）、夜色 `#241E1A`（今晚卡片） |
| 字 | 标题一律宋体 + 大字距，正文系统黑体——宋体是整个「文艺」感的来源 |
| 分隔线 | 不用实线，用虚线/点线（像票据） |
| 状态 | 不用圆角胶囊标签，用**旋转 6° 的印章** |
| 凭条 | 真·票根：左右两个圆缺口 + 中间撕口虚线 + 底部条码（条码宽度由订单号哈希生成） |
| 图标 | 13 个手绘线稿 SVG 现画的：吉他、麦克风、月亮、票根、酒杯、音符…不用任何现成图标库 |
| 文案 | 全程说人话：「几位朋友」「坐哪儿」「还没去 / 去过的」「今晚歇一天」「这桌已经有人订了」 |

## 6. 代码结构

```
pages/*          只管展示和交互，不直接碰数据格式
utils/api.js     所有数据进出的唯一出口，全部返回 Promise
utils/data.js    店铺配置（店名/桌子/时段/节目单），运营自己能改
utils/util.js    日期、哈希、取号等纯函数
```

`api.js` 现在的八个方法，就是以后云函数的八个接口：

| 方法 | 以后对应 |
|---|---|
| `getShop()` / `getShows(n)` / `getDates()` / `getSlots(date)` | 云数据库读配置 |
| `getTables(date, slot, people)` | 云函数：查当天占用 + 返回桌位图 |
| `createOrder(payload)` | 云函数：事务抢桌（防同一张桌被两人同时订） |
| `listOrders()` / `getOrder(id)` / `cancelOrder(id)` | 按 openid 查自己的单 |
| `listTodayOrders()` / `updateStatus(id, s)` | 店员端，要加权限校验 |

**现在没做、上云时必须补的两件事**

1. **抢桌并发**：两个人同时点同一张桌，必须在服务端用事务判一次，不能靠前端
2. **权限**：店员接口要校验身份（现在只是个前端口令，真上线要用云函数 + 白名单 openid）

## 8. 店里试点怎么跑（建议）

1. 先把 `data.js` 改成真实的桌子、真实的节目单、真实的电话地址
2. 开发者工具里自己走一遍，再让服务员用店员模式走一遍
3. 上云 + 发布体验版，印一张小卡片放在每张桌子上：「扫码订下周的位置」
4. 前两周**双轨**：电话/微信订座照常，小程序只是多一条路；服务员每天收工前对一次
5. 两周后看三个数：小程序订座占比、到店率（有多少订了没来）、服务员有没有抱怨
6. 没问题再考虑二期点单
