# 二期：把点单从美团搬回自己家

> 这份是方向和账本，不是排期。等一期订座在店里跑顺了再动。

## 1. 先算清楚省多少

美团/大众点评这类平台在一家店身上拿的钱，通常是三块：

1. **团购套餐的佣金**（按核销金额抽成）
2. **推广/竞价**（想被看见要花的钱）
3. **活动补贴分摊**（满减、新客券里店家出的那部分）

把你自己的数填进去算一次，这个表比任何话都有说服力：

| 项 | 填你的数 | 示例 |
|---|---|---|
| 月流水 | ____ | 20 万 |
| 其中走平台的比例 | ____ | 60%（12 万） |
| 平台综合抽成（佣金+推广+补贴分摊） | ____ | 8%（9,600 元/月） |
| 换成自己小程序后的成本 | 微信支付费率 **0.6%** + 云开发（一家店基本在免费额度内）+ 一次性开发 | 12 万 × 0.6% ≈ 720 元/月 |
| **每月差额** | | **≈ 8,900 元** |

> 微信支付普通商户费率按行业定，餐饮一般 0.6%，以签约时费率为准。

**但是**，有两笔账不能只看省下的佣金：

- 美团带来的**新客流量**是真的（尤其是路过搜索「附近酒吧」的人）。一刀切下掉，营业额可能先掉一截。
- 平台上的**评价和排名**是积累资产，断更会掉权重。

所以结论基本都是：**不是「换掉」，是「分流」**。

## 2. 分三步走，不要一刀切

| 阶段 | 做什么 | 平台怎么办 |
|---|---|---|
| 第一步（一期，现在） | 订座小程序，桌上放小程序码 | 美团照常，什么都不动 |
| 第二步 | 扫码点单上线。**老客、订过座的客人、到店扫码的客人走小程序**；小程序里给一点只有这里有的好处（常客第二杯半价、点歌优先、满额送一杯） | 美团只保留**引流型团购**（低价进店套餐），不再上高抽成的大套餐 |
| 第三步 | 看数据：小程序月活、复购、客单价。小程序自点占比稳定过半以后 | 美团退回「新客获客渠道」的角色，预算砍到够维持曝光即可 |

关键在第二步要给客人一个**非走小程序不可的理由**。
对一家民谣酒馆，最好的理由不是便宜，是**点歌**：小程序里能给今晚的歌手点一首、能看歌单、能存自己的「常点」。美团给不了这个。

## 3. 点单要做的东西（技术）

```
客人扫桌上的码（带桌号参数 ?table=B3）
   → 进小程序，自动落到 B3 这桌
   → 看酒单（分类：鸡尾酒 / 威士忌 / 啤酒 / 无酒精 / 小食）
   → 加购物车 → 下单 → 微信支付
   → 吧台收到新单（店员端响铃 + 列表）
   → 出品 → 送到 B3
   → 结账（可加单，可拆单 AA）
```

需要补的模块：

| 模块 | 说明 | 难点 |
|---|---|---|
| 商品库 | 酒单 CRUD、分类、沽清（卖完了要能一键下架） | 不难，但要让店员自己会改 |
| 购物车 / 下单 | 和桌号绑定，支持同桌多人各自点、合并到一张单 | 同桌并发，要用云数据库事务 |
| 微信支付 | 云开发支付或商户号直连；要处理退款 | 需要执照 + 餐饮类目 + 商户号 |
| 吧台接单端 | 新单提醒（响铃/震动）、制作中/已出品、打印小票 | 小票打印机对接（云打印机最省事） |
| 对账 | 每日营业额、分品类销量、取消/退款记录 | 老板最关心这一页 |
| 会员 | 储值、常客标记、生日提醒 | 可放三期 |

一期已经铺好的地基：
- 桌号体系（A/B/C/D 区 + 桌位图）点单可以直接复用
- `utils/api.js` 的分层方式照搬，加 `menu.js` / `cart.js` 即可
- 设计系统（`app.wxss`）已经定好，酒单页能直接套现成样式

## 4. 容易踩的坑

- **服务员的习惯**最难改。上线前让每个服务员在自己手机上走三遍流程，比写十页文档管用。
- **高峰期不能崩**。周六晚上 21 点同时二十桌点单，云函数并发和打印机排队要提前压一遍。
- **沽清**。卖完了没下架，客人点了付了钱做不出来，最伤。开单前先让吧台点一遍「今天没有什么」。
- **别急着关美团**。先并行三个月，看小程序占比爬到多少再决定砍多少预算。
- **发票和退款**要有人管，平台原来帮你兜的事现在是自己的。

## 5. 三期之后可以有的

- 点歌台：客人花 20 块点一首，钱分给歌手（这件事美团永远做不了）
- 常客墙：来过 10 次的名字印在店里小黑板上
- 演出售票：重点场次卖票 + 入场核销（一期的「取号 + 凭条」已经是雏形）
- 唱片/周边寄售
